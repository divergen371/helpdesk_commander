# 検出強化の追加手段の評価と決定（HC-27）

ClamAV 単体では未知のマルウェアや標的型文書の検出力に限界がある。HC-26 の評価基盤を
前提に、外部レピュテーション・多エンジン・CDR・動的解析を比較し、PII・コスト・
レイテンシ・運用負荷を含めて採用可否を決めた。実装は行わない。

決定日: 2026-11-15 / 決定: accepted

この文書を決定記録の正本とする。Backlog の decision は CLI が本文編集に対応していないため、
空のテンプレートはアーカイブした。

## 現状の検出範囲と残る穴

| 層 | 実装 | 残る穴 |
| --- | --- | --- |
| 形式検証 | 拡張子・MIME・マジックバイト（HC-19） | 形式として正しい悪性文書 |
| シグネチャ | ClamAV（深掘り・暗号化/上限検出、HC-23） | 未知・標的型、シグネチャ更新前 |
| 組織ルール | YARA（HC-25） | ルール未作成の検体 |
| 既知判定 | SHA256 許可/拒否・clean キャッシュ（HC-24） | 未知ハッシュ |
| 実行環境 | clamd サンドボックス（HC-21） | 検体を実行しない（静的のみ） |

## 評価基準

1. ファイル本体が外部へ出るか（PII・機密性）
2. ClamAV + YARA に対する追加の検出力
3. コスト（初期・従量・見積の不確実性）
4. レイテンシ（同期アップロードに耐えるか）
5. 運用負荷（可用性、障害時、ベンダー依存、監査）
6. 導入・維持の実装コスト

## 比較

| 手段 | 候補の例 | ファイル送信 | PII / 機密性 | コスト | レイテンシ | 運用負荷 | 判断 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 外部レピュテーション（ハッシュ照合） | 商用フィード（VT Enterprise、MetaDefender 等）、自前フィード、abuse.ch（商用契約時） | **不要**（SHA256 のみ） | 低（ハッシュは個人情報を含まない） | 商用契約または自前運用。無償枠は非営利限定 | 数百 ms | 中（契約・更新・障害対応） | **採用**（HC-41、既定は無効） |
| 外部レピュテーション（ファイル送信型） | VirusTotal、MetaDefender Cloud、Hybrid Analysis | **必要** | 高（文書内容・顧客情報） | 従量。要見積 | 秒〜 | 中 | 見送り（既定） |
| 多エンジン | VirusTotal、MetaDefender Cloud、Joe Sandbox | **必要** | 高 | 高（従量・契約） | 1〜10 秒 | 中〜高 | 見送り（既定） |
| CDR | OPSWAT MetaDefender CDR、Glasswall、Votiro | クラウドは必要。オンプレ可 | 中（オンプレなら低） | 高（初期・契約） | 秒 | 中 | **PoC**（HC-42） |
| 動的解析 | Joe Sandbox、ANY.RUN、Hybrid Analysis、CAPE/DRAKVUF | **必要** | 高 | 高 | 分単位 | 高（VM 運用・回避対抗） | 見送り（既定） |

- 価格・SLA・データ保持条件はベンダー見積と契約条件の確認が必要で、本評価では
  確定していない。比較は「採用可否の方向性」を決めるためのもの。
- VirusTotal の Public API は、ファイルを提供しない業務フローと商用製品での利用を
  利用規約で制限している。VT を候補にする場合は Premium / Enterprise の契約が前提。
- abuse.ch（MalwareBazaar）の無償 API も非営利利用に限定されている。商用製品で使う場合は
  契約条件の確認が必要。「無料でハッシュ照合できる」前提を置かない。
- したがって実装は特定ベンダーに依存させず、**商用利用可能な契約または自前フィードの
  エンドポイントを設定する**形にする。既定は無効。
- ハッシュ照合はファイル内容を送らないが、照会先に「どのハッシュを調べたか」は渡る。
  それ自体が機密情報になる運用（未公開製品の文書など）では無効化できるようにする。

## 決定

### 1. 採用: ハッシュ照合による外部レピュテーション（HC-41）

- スキャン前に SHA256 で既知マルウェアを照会する。ファイル本体は送らない。
- 照会先は設定で差し替え可能なベンダー非依存の実装にする。既定は無効で、商用利用可能な
  契約または自前フィードを用意した運用だけが有効化する。
- 一致したら `infected` として隔離する。判定理由と照会元を `scan_note` / 監査ログに残す。
- API 障害・タイムアウトは **fail-open**（既存の ClamAV/YARA の結果を変えない）。
  レピュテーションは補助であり、可用性をアップロードの単一障害点にしない。
- 同一ハッシュの照会結果はキャッシュし、レート制限とコストを抑える。
- 会社単位で有効/無効を設定でき、無効時は外部へ一切照会しない（ハッシュ自体が
  機密になり得る運用のため）。
- 判定の優先順位は **ローカル deny > 外部レピュテーションの infected > ローカル allow >
  clean キャッシュ > 通常スキャン**。外部の infected は allow 規則や clean キャッシュで
  覆い隠さない。deny は外部照会の結果にかかわらず常に最優先。
- 外部照会はファイル本体を送らず、SHA256 のみを送る。

### 2. PoC: オンプレミス CDR（HC-42）

- 対象は Office（docx / xlsx / pptx）と PDF。マクロ・スクリプト・埋め込みオブジェクトを
  除去して再構築する。
- ファイルを外部に出さない構成（オンプレミスまたはプライベートクラウド）を必須にする。
- 変換後の見た目・数式・互換性の忠実性、レイテンシ、コスト、運用負荷を測る。
- 採用判断は PoC の結果で行う（本決定では「検討する」まで）。

### 3. 見送り: 多エンジンと動的解析（既定）

- ファイル本体を外部へ送る方式は、現行の PII 方針（cloak + 社内照合、外部送信の最小化）と
  両立しない。既定では採用しない。
- 再検討の条件:
  - 顧客の明示同意とデータ処理契約がある
  - 専用テナント・専用リージョン・保持期間ゼロなどの契約が可能
  - オンプレミスで完結する製品を選べる
  - P1/SEV1 など、対象を高リスクなチケットに限定する運用ができる
- 動的解析は同期アップロードに組み込まない。導入する場合も非同期の追加検査とし、
  「検査待ち」の状態を UI に出す。

## 評価の限界

- ベンダー試用・見積・法務確認は未実施。価格と契約条件は実導入時に再評価する。
- HC-26 のコーパスは EICAR と良性ファイルのみで、未知検体の検出力を代表しない。
- 本決定は「今の構成と運用方針に対する判断」であり、将来の脅威・規制・顧客要求が
  変われば再検討する。
