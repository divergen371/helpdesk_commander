## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ClamAV の検出力はシグネチャの鮮度に強く依存するが、現状は更新の自動化・鮮度監視・更新後の再スキャンがない。古いシグネチャで clean になったファイルが残り続けるため、更新運用と再検査を仕組み化する。
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
実装: AttachmentSignature リソース（attachment_signatures、name=clamav の単一レコード、migration 20261106143005、dev/test DB 適用）を追加。Attachments.Signatures で record/upsert・freshness（signature_at なければ checked_at、既定 24h 閾値）・ensure_fresh（enforce 時は stale/unknown を {:error, :signature_stale}、非 enforce 時は Logger.warning）。
更新: UpdateSignaturesWorker（queue :attachments、max_attempts 3、毎日 03:15 の Cron）が :attachment_signature_update_command（本番既定 freshclam、開発/テスト nil）を 300 秒タイムアウトで実行。成功時に ScanMetadata からエンジン/版/シグネチャ日時を保存し、clean/skipped 添付を再スキャン。失敗時は status=error と last_error を保存して Oban 再試行。
再スキャン: Attachments.rescan_outdated/1 が clean/skipped を inserted_at 昇順・:attachment_rescan_limit（既定 500）件ずつ pending 化して enqueue。冪等（pending 化で対象から外れる）。enqueue 失敗は failed（note=rescan_enqueue_failed）として隔離し他へ波及させない。ingest は Signatures.ensure_fresh を通過後に形式検証。
設定: runtime.exs に ATTACHMENT_SIGNATURE_UPDATE_COMMAND / MAX_AGE_HOURS / ENFORCE / ATTACHMENT_RESCAN_LIMIT。docs/OPERATIONS_SCANNER.md（更新・ブートストラップ・鮮度・再スキャン・監視）と DESIGN_ATTACHMENTS を更新。
テスト: Signatures 6 件、UpdateSignaturesWorker 3 件、鮮度ゲート + 上限付きバッチ再スキャンの冪等性 2 件を追加。
検証: mix precommit 402 passed（13 properties / 389 tests）、coveralls 82.4%（3401 / 4129 行）、dialyzer 0 errors、ash.codegen --check 成功。
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
シグネチャ更新を定期実行する UpdateSignaturesWorker（毎日 03:15、本番既定 freshclam、失敗は status=error 保存＋Oban 再試行）を追加し、エンジン・版・シグネチャ日時を attachment_signatures に単一レコードで保存する。鮮度は既定 24 時間で判定し、閾値超過・未記録は警告、ATTACHMENT_SIGNATURE_ENFORCE=true ならアップロードを拒否する。更新成功後は clean/skipped の添付を上限 500 件ずつ pending 化して再スキャンし、冪等性と失敗時の failed 隔離を担保した。テストは Signatures 6 件・Worker 3 件・鮮度ゲートとバッチ再スキャン 2 件を追加し、mix precommit 402 passed（13 properties / 389 tests）、coveralls 82.4%、dialyzer 0 errors。運用手順は docs/OPERATIONS_SCANNER.md。
