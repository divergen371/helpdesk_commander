## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
docs/OPERATIONS_BACKUP.md を追加: pg_dump -Fc / pg_restore の手順、添付ディレクトリの並行バックアップ、3 世代・DB 外保管の要件、RPO/RTO。
復元後検証を priv/verify/verify_restore.exs として実装: companies/users の cloak 属性を CLOAK_KEY で復号し、PiiHash で email_hash/name_hash と照合（PII_HMAC_SECRET の整合確認）。メール/会社名を出力するので本番データでは許可環境で実行の注意を記載。
鍵の保管: CLOAK_KEY / PII_HMAC_SECRET / COMPANY_CODE_HMAC_SECRET を Git 管理外（シークレットマネージャ or 0600 .env）、オフライン含む 2 系統で保管。
ローテーション: CLOAK_KEY は Cloak の複数 cipher（新鍵 default + 旧鍵 retired、tag 切り替え）→ 全行再書き込み → 検証後 retired 削除。HMAC 側 secret は復号した平文からの再ハッシュで更新。年 1 回 + インシデント時。
演習: ローカル（dev DB・dev 鍵）で pg_dump → createdb + pg_restore → verify_restore.exs を実行し、会社 1 件 / ユーザー 3 件の復号・HMAC 一致を確認。ステージング本鍵の演習は運用手順（四半期）として docs に明記。
検証: mix precommit 348 passed（13 properties / 335 tests）で既存テストに回帰なし。
