## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
実装: 新規モジュール Attachments.MagicBytes — 先頭 512 バイトを読み、署名一致
（png / jpg / gif / webp / pdf / zip 系 = PK、docx / xlsx / pptx 共有）、表示可能テキスト
（NUL・制御文字なし、UTF-8 許容、空ファイル含む）、認識不能バイナリ（unknown_binary）を判定。
FilePolicy を拡張: 拡張子 → MIME →（既存チェック後）マジックバイトの三点照合。format は
対応拡張子のみ許可、text は txt / csv のみ許可、unknown_binary は全拡張子拒否、
read_error も拒否。不一致は :content_magic_mismatch で ingest がアップロードを拒否（AC#1/#3）。
実行ファイル（MZ / ELF）を .txt にリネームしたケースは NUL・制御文字を含むため text と
判定されず拒否される（AC#2 の画像 / PDF / ZIP / Office 署名テストも追加）。
テスト: MagicBytes 単体 6 件（署名検出・テキスト判定・UTF-8・空ファイル・unknown_binary /
read error）+ FilePolicy 4 件（許可形式 16 パターン / 拡張子不一致 / txt 偽装 / 読めないファイル）
+ ingest 統合 1 件（MZ 偽装 .txt の拒否）。既存の取込フローは note.txt テキストのまま回帰なし。
既存テストの photo.png は表彰 PNG ヘッダーの実体に変更（"HX_本来の PNG バイト列"）。
docs: docs/DESIGN_ATTACHMENTS.md の「容量・形式」を三点照合・テキスト判定・OOXML 制約つきで更新。
検証: mix precommit 368 passed（13 properties / 355 tests）、coveralls 82.2%（3260 / 3968 行）、
dialyzer 0 errors、ash.codegen --check 成功。

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
添付ファイルの形式検証を拡張子・MIME・実体（マジックバイト）の三点照合にした。
新規 Attachments.MagicBytes が先頭 512 バイトを判定し、png / jpg / gif / webp / pdf /
zip 系（PK 署名、docx / xlsx / pptx 含む）は対応拡張子のみ許可。署名なしで表示可能テキスト
（NUL・制御文字なし、UTF-8 許容）は txt / csv のみ許可。実行バイナリ等の認識不能な中身は
どの拡張子でも拒否し、MZ（PE）を .txt に偽装したファイルもアップロードを拒否される。
不一致は :content_magic_mismatch。テストは MagicBytes 6 件 + FilePolicy 4 件
（許可形式 16 パターン含む）+ ingest 統合 1 件を追加し、mix precommit 368 passed
（13 properties / 355 tests）、coveralls 82.2%、dialyzer 0 errors。
docs/DESIGN_ATTACHMENTS.md を更新済み。
