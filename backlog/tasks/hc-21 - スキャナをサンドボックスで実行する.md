## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
スキャナ自体が攻撃面にならないよう、外部ネットワークなし・読み取り専用・非 root・cap-drop・リソース制限の環境で動かす。Elixir/Erlang には seccomp/Landlock を扱う成熟したライブラリがなく、MuonTrap は cgroup 制限のみで隔離機能はない。そのため clamd サイドカーを第一候補とし、アプリに Docker ソケットを渡さない構成にする。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
実装: docker/clamav/Dockerfile（Alpine 3.22 + clamav 1.4.3、clamav uid 100/gid 101）+ clamd.conf / freshclam.conf。docker-compose.yml に clamd（scanner_internal=internal:true・read_only・user 100:101・cap_drop ALL・no-new-privileges・mem 1g / cpus 1.0 / pids 128）と clamav-db-updater（egress あり、clamav_signatures volume のみ共有）を追加。ポート公開は internal ネットワークでは不可のため、ホスト開発用に docker-compose.clamd-dev.yml（開発専用の緩和）を追加。
アプリ側: Attachments.Clamd を新設し、TCP INSTREAM（4 バイト長ヘッダ + 終端）でファイルを送る。Docker ソケット・共有ボリューム不要。Scanner は clamd 設定をコマンドより優先。接続失敗・タイムアウト・ERROR 応答は {:error, ...} → failed 隔離（HC-16/18 の fail-closed・再試行を維持）。ScanMetadata は clamd VERSION から engine/version/signature_at を取得。UpdateSignaturesWorker は clamd 設定時に RELOAD + VERSION で更新・記録する（freshclam は updater コンテナ）。
検証（実 clamd 1.4.3 / arm64）: read_only rootfs、uid=100(clamav)、CapEff=0、NoNewPrivs=1、mem=1GiB / cpus=1.0 / pids=128 を docker inspect で確認。internal ネットワークで 1.1.1.1:53 / 8.8.8.8:53 への接続が不可（egress なし）を確認。priv/verify/verify_clamd.exs で PING / VERSION（ClamAV 1.4.3/28176/Sat Nov 7 06:24:18 2026）/ 良性 clean / EICAR infected（Eicar-Test-Signature FOUND）を確認。実アプリ経路（ingest → scan_attachment）でも benign=clean・EICAR=infected（隔離、ダウンロード不可）を確認。プロトコル単体・タイムアウト・ERROR 応答は ClamdFakeServer で 9 件 + Scanner/ingest 統合を追加。
検証: mix precommit 438 passed（13 properties / 425 tests）、coveralls 82.6%（3698 / 4479 行）、dialyzer 0 errors、ash.codegen --check 成功。docs/SANDBOX_SCANNER.md に構成・起動・シグネチャ更新・EICAR 検証・制約を記載。
