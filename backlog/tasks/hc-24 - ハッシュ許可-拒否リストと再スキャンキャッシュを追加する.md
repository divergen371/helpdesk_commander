## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
同じファイルを毎回スキャンするのは無駄が大きく、既知の安全なファイルや明確な拒否対象を運用で管理できていない。SHA256 をキーにしたキャッシュと許可/拒否リストを追加し、検出と運用の両方を改善する。
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
実装: AttachmentHashRule リソース（attachment_hash_rules、company_id NULL=全体、sha256/action/note、migration 20261106143658）と Attachments.HashRules（list/decision/add/remove、deny 優先、スコープ別、監査ログ）を追加。管理画面 /admin/attachment-rules（admin_required）で全体/自社の deny/allow を追加・削除できる LiveView を追加。
ingest の判定順: deny -> status=blocked で即隔離（ダウンロード不可、UI「ブロック」）、allow -> 形式検証は維持して clean、clean キャッシュ（同一 SHA256 + 現行エンジン/版/シグネチャ日時が一致し、同ハッシュの infected 記録なし）-> スキャン省略で clean、それ以外 -> pending + Oban ジョブ。シグネチャ未記録時はキャッシュしない fail-safe。TicketAttachment の scan_status に blocked を追加。
監査: ルールの created/updated/deleted と decision（deny/allow/cache_hit）を Logger に attachment_hash_rules として記録。
テスト: HashRules 4 件（CRUD + 監査ログ / deny 優先 / 会社スコープ / 不正 action）、ingest 4 件（deny 隔離 / allow のスキャン省略と形式検証維持 / シグネチャ一致キャッシュ / 未記録時はキャッシュなし）、管理画面 2 件を追加。

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
SHA256 をキーにした許可/拒否リストと clean キャッシュを追加した。attachment_hash_rules（全体/自社スコープ）を管理画面 /admin/attachment-rules から管理でき、判定は deny > allow > clean キャッシュ > 通常スキャンの順。deny は status=blocked として即隔離、allow は形式検証を維持してスキャンを省略、clean キャッシュは同一ハッシュかつ現行シグネチャ（engine/version/signature_at）一致時のみ再利用し、infected 記録やシグネチャ未記録時はキャッシュしない。ルール変更と判定結果は監査ログ（attachment_hash_rules）に残す。テストは HashRules 4 件・ingest 4 件・管理画面 2 件を追加し、mix precommit 412 passed（13 properties / 399 tests）、coveralls 82.3%、dialyzer 0 errors。
